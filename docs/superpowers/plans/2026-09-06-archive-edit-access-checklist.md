# Чек-лист проверки: доступ к редактированию архивного года

Сервер уже запущен локально: **http://localhost:3000**

## 1. Подготовка

- [ ] Если в базе всего один период сбора — открыть новый период через Админку → «Период сбора» → «Открыть новый период» (это создаст архивный год из текущего, аккуратно — это реальное изменение на общей базе).
- [ ] Выбрать тестового сотрудника (можно себя, если роль позволяет) для выдачи доступа.

## 2. Выдача доступа

- [ ] Админка → «Период сбора» → блок «Доступ к редактированию архива».
- [ ] Выбрать сотрудника и архивный год в выпадающих списках.
- [ ] Нажать «Выдать на 24 часа» → появляется в списке ниже с обратным отсчётом.

## 3. Проверка у сотрудника

- [ ] Зайти под этим сотрудником, открыть любое доступное ему подразделение.
- [ ] Сверху должен появиться переключатель: «[Текущий год] · [Архив, до …]».
- [ ] Переключиться на архивный год → «Шаг 1. Участники рынка» должен исчезнуть, остаётся только «Данные по рынку».
- [ ] Данные должны быть именно архивного года (или пусто, если их там не было).

## 4. Редактирование и сохранение

- [ ] Изменить/добавить значение оклада → нажать «Сохранить».
- [ ] Должно появиться «Архивные данные сохранены».
- [ ] Переключиться обратно на текущий год в том же баннере → убедиться, что текущий год не изменился.
- [ ] Снова переключиться на архивный год → убедиться, что правка сохранилась.

## 5. Проверка ограничений (по желанию, для уверенности)

- [ ] Под другим сотрудником без выданного доступа — переключателя года быть не должно вообще.
- [ ] Если текущий период закрыт — сохранение в архивный год всё равно должно работать у сотрудника с доступом (это была одна из починенных находок).

## 6. Отзыв доступа

- [ ] Админка → «Доступ к редактированию архива» → «Отозвать» у нужной строки.
- [ ] Зайти заново под этим сотрудником → переключатель года должен пропасть.
