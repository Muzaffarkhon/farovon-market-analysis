# Сопоставление должностей опроса (07.09.2026)

## Проблема

В `surveys` было **232 активные строки** (40% от 582) с `pos_our = «(не сопоставлено)»` —
данные по зарплатам конкурентов, где при импорте CSV звание конкурента (`pos_their`)
не привязалось к должности Фаровона из `dictionary_positions`. Такие строки не
попадают в дашборд зарплатных вилок и в бенчмаркинг.

Разных званий среди них — **121**, значительная часть на таджикском
(`Намояндаи савдо`, `Қолабрез`, `Кафшергари барқӣ`…).

## Решение

Ручная карта `pos_their → pos_our` — [`data/posmap-2026-09-07.json`](data/posmap-2026-09-07.json).
Все целевые значения существуют в `dictionary_positions` (новые должности не заводились).

- Покрыто **120 из 121** звания → **231 из 232 строк**.
- Не сопоставлено: `«(не указано)»` — 1 строка без звания.
- `conf: "h"` — точное совпадение со справочником или однозначный перевод;
  `conf: "m"` — решение оператора (напр. `Челонгар → Слесарь`,
  `Сардори баст → Начальник смены`, `Устои сех → Мастер`); подтверждены в чате.

## Применение

Разовый скрипт (не в репозитории, лежал в сессионном scratchpad):

```
UPDATE surveys SET pos_our = <to>
WHERE state = 'активна' AND pos_their = <from>
  AND (pos_our IS NULL OR TRIM(pos_our) = '' OR pos_our = '(не сопоставлено)')
```

по каждой паре из карты, плюс запись в `audit_log`
(`action = 'сопоставление должностей опроса (posmap)'`).

Карта сохранена как справочный артефакт: если импорт CSV снова оставит эти
звания без пары — переиспользовать, а не сопоставлять заново.
