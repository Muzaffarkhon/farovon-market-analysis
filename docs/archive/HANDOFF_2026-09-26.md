## 2. Дизайн-ревью по жёсткой обратной связи пользователя

Пользователь резко раскритиковал внешний вид («нарисовано карандашом», сравнение с Google/Uber/Apple). Не стал отвечать общими словами — нашёл и показал конкретный дефект:

- **Баг в `ForkBar`** (`web/src/design/ForkBar.tsx` + `.module.css`) — шкала зарплатной вилки на дашборде («Топ должностей по числу наблюдений»). Когда P25≈P75 (частый случай — почти все наблюдения на одной зарплате), капсула схлопывалась в 0px и пропадала, а горизонтальная линия min-max + вертикальная риска медианы образовывали голубой крестик вместо нормальной шкалы. Почти наверняка это и вызвало ощущение «от руки».
  - Правка: у капсулы `min-width: 10px` (никогда не схлопывается), рельс-подложка на всю ширину (`.track::before`), риска медианы теперь белая полоска поверх капсулы, а не второй конфликтующий брусок того же цвета.
- **Системная правка**: почти все карточки/плитки/обёртки таблиц (`border: 1px solid var(--border); background: var(--surface)`) не имели тени — плоские, только тонкая рамка, из-за чего весь интерфейс выглядел как wireframe. Добавил `box-shadow: var(--shadow)` (токен уже существовал, использовался только в оверлеях) во все такие правила разом — `KpiTile`, `AdminHub`-карточки, карточки Реестра/Грейдирования/Рисков/Координации/CompReview, все `.tableWrap`/`.tableWrapFill`. Затронутые файлы (11 штук) — см. `git status`.

Проверено вживую (дашборд, админка) — заметно объёмнее, крестика на слайдере больше нет. Тесты (57/57 файлов, 304/304) и сборка проходят чисто.

## 4. Новая фича: сброс голосования комиссии (по ЗП)

Пользователь попросил: «дай возможность суперадмину принудительно сбросить голосование». Реализовано симметрично уже существующему `forceDecide` (принудительное одобрение/отклонение) — тот же уровень доступа (capability `comp:admin`, не обязательно буквально логин `admin`).

- **Backend** — новая функция `resetVote(employeeId, actorLogin)` в `src/services/compReviewService.js` (рядом с `forceDecide`): удаляет все строки из `comp_committee_votes` по сотруднику, возвращает `comp_request_employees.status` в `'active'` и `decided_at` в `NULL`, пишет в журнал активности. Работает только пока сама заявка ещё в статусе `'committee'` (тот же `requireStatus`, что у `forceDecide`) — если заявка уже ушла дальше (payroll/closed), сброс недоступен, это осознанное ограничение, не баг.
- Роут: `POST /comp/employees/:employeeId/reset-vote`, capability `comp:admin` (`src/routes/api.js`).
- Контроллер: `exports.resetVote` в `src/controllers/compReviewController.js`, пишет в `audit_log`.
- Фронтенд: `compReviewApi.resetVote()` → `useCompReview.ts` (`resetVote` в списке actions) → `RequestScreen.tsx` прокидывает в `EmployeeCard` → кнопка «Сбросить голосование» в `EmployeeCard.tsx`:
  - в блоке активного голосования (рядом с «Напомнить не проголосовавшим»), видна только если `votedCount > 0`;
  - в блоке после совместного совещания (`committee_meeting`), рядом с «Одобрить»/«Отклонить» по итогам встречи.
  - Обе — с подтверждением через `useConfirm()`, доступны только `access.isAdmin` (то же самое, что уже гейтит `forceDecide`).

**Не проверено вживую через браузер** — в тестовой базе (`data/dev.db`) не оказалось готовой заявки на этапе `committee` с поданными голосами, чтобы кликнуть кнопку глазами. Проверено: `node --check` на все backend-файлы, `npx tsc -b` чисто, backend-тесты `npm test` — 251/251, frontend `npx vitest run src/features/compReview` — 6/6 (без новых кейсов конкретно на resetVote — стоит добавить, если будет время). Логика зеркальна уже проверенному в проде `forceDecide`, риск невысокий, но живая проверка кнопки не помешает.
