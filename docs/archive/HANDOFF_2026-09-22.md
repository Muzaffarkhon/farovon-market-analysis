## 3. Что нашли при обследовании — чинить отдельно

Три параллельных обследования кода (роли и безопасность, сбор и аналитика, грейдинг / бот / поддержка) вскрыли следующее. Всё это вошло в ТЗ отдельными разделами, но актуально и для текущей системы.

**Безопасность:**

1. **Маршруты сбора не защищены правами.** `/survey/*` в `src/routes/api.js` проверяют только авторизацию — анкету может заполнять любой пользователь с любой ролью. Ограничение только по подразделениям.
2. **Защиты от CSRF нет вообще**, при этом сессия принимается из куки `farovon_session`.
3. **CSP разрешает `unsafe-inline`** в `script-src`, в клиенте около 259 мест присваивания `innerHTML` с ручным экранированием через `esc()`.
4. Принимаются **устаревшие несолёные SHA-256 хеши** паролей (есть авто-миграция на bcrypt при входе).
5. Связь пользователь ↔ подразделение **строковая**, авторство записи определяется сравнением ФИО.
6. Роль `cb` по умолчанию получает **все 25 прав**.

**Данные, которые собираются впустую:**

`source` (источник) и `trust` (надёжность) **обязательны при заполнении, но не выводятся ни в один отчёт и не фильтруются**. То же с `schedule`, `extra` (прочие выплаты), `note` и `divisions.survey_note`. Люди тратят время на ввод, который ни на что не влияет. Ещё: конвертации валют в вилках нет (`fxService` работает только в бенчмаркинге), разреза по грейдам нет.

**Расхождение валидации:** график, источник и надёжность обязательны **на клиенте** и **не обязательны на сервере** — через API проходит то, что интерфейс не даст сохранить.

**Сломанное и заброшенное:**

- `telegramService.sendMassReminder()` считает готовность по устаревшей колонке `competitors.actual` и не фильтрует по активному периоду — фактически сломан. Команда `/status` в боте считает правильно, брать её за основу.
- **Обращения в поддержку из интерфейса не уведомляют администраторов вообще** — уведомление шлётся только по Telegram-тредам. Главный дефект поддержки.
- **Планировщика и крона в системе нет** — ни Vercel Cron, ни node-cron. Все напоминания — ручная кнопка.
- Вебхук Telegram **не идемпотентен** (повторная доставка обрабатывается заново); подпись Mini App `initData` не проверяется.
- Мёртвый код: таблица `grading_position_hints` заполняется миграцией и нигде не читается; `grading_block_results` объявлена и не используется; `job_evaluations.group_type` — рудимент.
- В комментариях кода встречается «6 факторов» грейдинга (их 7, К7 добавлен 17.09) и «поллинг 8 с» (фактически 20 с) — устарело.

## 4. ТЗ на переписывание интерфейса

`docs/ТЗ_переписывание_интерфейса_2026-09-22.md` — 17 разделов, написано для передачи исполнителю (Fable 5.1).

**Границы:** переписывается только клиент, на React с компонентами. Сервер (`src/`) и схема БД остаются, данные не мигрируют.

**Ключевые решения заказчика, зафиксированы в §16 ТЗ — не пересматривать:**

1. **Собирают все роли** — сотрудник, начальник отдела, руководитель направления, HR BP. HR BP **координирует процесс**, а не утверждает записи.
2. **Модерации и статуса «на уточнении» не будет.** Основание: сборщик сам выбирает компании для сравнения и сам отвечает за достоверность.
3. **Грейд в анкете не нужен** — только импортом.
4. **Сбор годовой** — влияет на ритм напоминаний в боте.
5. **Шаги 1 и 2 объединяются в один.** Сейчас оба экрана выглядят одинаково (сетка карточек должностей) и люди их путают. Выбор компаний переезжает внутрь листа заполнения кнопкой «Добавить компанию».
6. **Появляется отметка «Сравнивать не с кем»** — четвёртое состояние карточки. Закрывает существующую дыру: сейчас осознанно пустая должность и забытая выглядят одинаково.
7. **Прогресс переезжает на должности:** «сколько должностей получили решение из скольких», знаменатель равен штатке отдела. Дробь по компаниям остаётся внутри должности как вспомогательная.

## 6. Грабли этой сессии

- **`.env` указывает на ПРОДАКШН-базу** (`libsql://farovon-market-analysis-muzaffarkhon`). Локальный `npm run dev` читает и пишет боевые данные. Перед любыми скриптами по БД проверять, куда смотрит конфиг.
- **Порт 3000 бывает занят** сервером из другого чата. Запуск на другом порту в PowerShell: `$env:PORT=3002; npm run dev`.
- **Vercel замораживает функцию сразу после ответа** — все побочные действия (отправка в Telegram и подобное) выполнять **до** `res.end()`. В текущем коде учтено, не сломать.
- Локальная копия может отставать от `origin/main`. Сегодня утром отставала на 4 коммита, из-за чего часть работы была сделана по устаревшему коду и переделана. **Начинать сессию с `git fetch` и сверки.**
