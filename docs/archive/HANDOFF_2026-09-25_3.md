## 1. Багфиксы (живое тестирование пользователем)

- **Зависание при вводе в заявке «Изменение ЗП»**: поля «Документ-основание», «Общий комментарий» и «Дата вступления в силу» сохранялись на каждый символ/частичный ввод без debounce — запрос уходил на сервер на каждую букву (а сохранение там само по себе тяжёлое, N+1 к Turso), запросы копились быстрее, чем сервер успевал отвечать, UI вставал колом. Исправлено: сохранение теперь по `onBlur`, локальный черновик-стейт в `RequestScreen.tsx`. Заодно распараллелил `loadEmployeeRows`/`getRequest` в `compReviewService.js` (`Promise.all` вместо последовательных `await` в цикле) — сама операция сохранения тоже стала быстрее.
- **Ссылка «Прикрепить через Telegram» не открывалась**: `window.open()` вызывался после `await` сетевого запроса — браузер (особенно на телефоне) блокирует такое как попап без связи с кликом пользователя. Исправлено: вкладка открывается синхронно в обработчике клика (`window.open('', '_blank')`), адрес подставляется в неё после получения ссылки (`EmployeeCard.tsx`).
  - Отдельно всплыл случай — на конкретном ноуте пользователя `t.me` не резолвился вообще (DNS-блокировка на уровне сети/провайдера, не связана с кодом). Диагностировали через `Resolve-DnsName`/DNS-over-HTTPS/`Test-NetConnection`, решили включением Secure DNS (DoH) в самом Chrome (`chrome://settings/security`) — прав администратора Windows не требует. Просто держать в уме, если кто-то ещё пожалуется на «Telegram не грузит» именно на конкретном ноуте/сети, а не в целом.
- **Вложения скачивались вместо просмотра**: `Content-Disposition: attachment` → `inline` в `downloadAttachment` (`compReviewController.js`) — PDF/картинки теперь открываются во вкладке; Word/Excel всё равно скачаются, это уже поведение браузера.

## 2. Доработка «Изменение ЗП» по техзаданию (сверка + реализация)

Пользователь прислал `.docx` техзадание (изначально писалось под Битрикс24). Сверил с текущей реализацией (агент прошёлся по коду), нашёл расхождения, реализовал всё, что не упиралось в недостающие бизнес-данные:

- **C&B: рыночный диапазон** — было одно поле «медиана рынка», стало три: `marketMin`/`marketMedian`/`marketMax` (колонки `market_min`, `market_max` рядом с уже существующей `market_median` в `comp_request_employees`). UI — три инпута вместо одного в `EmployeeCard.tsx`.
- **Кадровик** — раньше дата внедрения ставилась автоматически (`CURRENT_TIMESTAMP`) без возможности её поменять и без комментария. Теперь: поле «Дата внедрения» (по умолчанию сегодня, можно поменять) + необязательный комментарий, оба сохраняются (`payroll_comment`, `payroll_effective_date`) и видны после закрытия заявки.
- **Назначаемая должность при переводе** — новое поле `new_position`, выбор из справочника должностей (новый эндпоинт `GET /comp/positions`). Если указана и отличается от текущей — вилка дохода и результат грейдинга считаются по **новой** должности, а правило «не чаще раза в 6 месяцев» **не блокирует** перевод на другую позицию (блокирует только повторный пересмотр той же должности). Логика — `checkEligibility({ ..., positionChanged })` в `compReviewLogic.js`.
- **HR BP** — новое поле, выбор из пользователей с ролью `hrbp` (роль уже существовала в системе, не хватало только этого поля в заявке). Новый эндпоинт `GET /comp/hr-bp`.
- **Третий вариант решения комиссии — «отправить на совместное совещание»** — рядом с «за»/«против». Нужно такое же большинство от состава комиссии, как и для за/против (`committeeOutcome` в `compReviewLogic.js` — три исхода вместо двух). Сотрудник уходит в статус `committee_meeting`, заявка **не закрывается**, пока по нему нет финального решения. После офлайн-встречи админ вручную вносит итог теми же кнопками «Одобрить»/«Отклонить» (`forceDecide` теперь принимает и `active`, и `committee_meeting`).
- **Результат грейдинга в заявке** — балл и грейд из модуля «Оценка должностей» подтягиваются автоматически через существующую связку `grading_block_assignments (unit, position) → block_key` → `job_evaluations (block_key, job_title)`. Видно и C&B, и комиссии (`gradingScore`/`gradingLevel` в карточке сотрудника). Снимок берётся на момент добавления/изменения строки, как и вилка дохода — не живой линк.
- Заодно доименование «Пересмотр ЗП» → «Изменение ЗП» в оставшихся местах: пункт меню для обычных пользователей, заголовок экрана заявки, записи в журнале аудита (`изменение ЗП: ...` вместо `пересмотр ЗП: ...`).

Все миграции — аддитивные (`ensureColumn`), безопасны для прод-базы с реальными данными. Бэкенд-тесты (`test/compReviewLogic.test.js`, 15/15) и фронтенд-тесты comp-review (9/9) зелёные на каждом шаге.

### Отложено — нужны данные от пользователя, не техническое решение

- **«Тип штатного расписания»** — поле из ТЗ, список допустимых значений пользователь ещё не дал. Пока не добавлял.
- **Состав комиссии «5 или 3 человека по должности»** — в самом тексте ТЗ помечено «списки дополним», то есть правила маршрутизации («какая должность → в какую комиссию») ещё не существует даже на бумаге. Сейчас комиссия в системе — одна общая на все заявки (`comp_committee_members`, плоский список), это осознанно не трогали. Ждём от пользователя сам список правил, тогда добавлять.
