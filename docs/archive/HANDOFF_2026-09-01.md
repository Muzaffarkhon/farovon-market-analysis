### Смежная группа (`group_key`) — обсудили, НЕ делаем
Пользователь думал про группировку по регионам «заполнить раз → на все площадки». Решили: **оклады по регионам различаются**, данные держим пер-регион. Реализовано через `divisions.region` + фильтр/вкладку (#56/#57), а не через `group_key`. Подпись в UI «должность вносится один раз, не по каждой площадке» — **вводит в заблуждение** (код так не делает: `group_key` даёт только общий список должностей + подсказки компаний). Кандидат на правку: убрать/переписать эту подпись.

## 7. Полезные факты про кодовую базу

- **Роли:** `admin`, `cb`, `hrbp`, `dir_head`, `head`, `user` + конструктор кастомных ролей (`roles`, `role_capabilities`). У `admin` все права всегда.
- **Суперадмин** = учётка с логином `admin` (та же, что `telegramController` зовёт «системным администратором»). Единственная, кому можно трогать других админов. `isSuperadmin()` в `adminController.js`.
- **Кто что видит:** `admin`/`cb` — «Отчёт по подразделениям» (read-only) + Дашборд + Бенчмаркинг + Админка; редактируемого «Мои подразделения» у них нет. Его видят `hrbp`/`dir_head`/`head`/`user`.
- **`S.ro` (read-only фронт):** `period.state==='закрыт' && role!=='hrbp' && !isElevated`. Для hrbp и admin/cb всегда false.
- **Владение строками `surveys` (`isOwnedByOther`):** admin/cb правят всё; остальные — только свои (по ФИО/логину) + импортные (`source` начинается с «импорт») как ничьи.
- **Дашборд «вилки»:** фронт `openDashboard` → `apiCBDashboardExtended` → `POST /api/dashboard/extended` → `getCBDashboard` → `getExtendedAnalytics(filters, {unitFilter})` в `src/services/analyticsService.js`. Фильтры: `dir`, `hrbp`, `region`, `search`. Ответ: `summary`, `positions`, `rows` (реестр), `hrbpProgress`, `dirProgress`, `regions`, `regionStats`, `topBenefits`, `bonuses`, `topCompetitors`, `scoped`.
- **«Сводка по подразделениям»:** фронт `openDash` → `POST /api/dashboard/hrbp` → `getHRBPDashboard` (своя фильтрация по роли).
- **`divisions` доп-колонки** (миграции `ensureColumn`, идемпотентно, при старте): `code`, `group_key`, `parent_unit`, `org_role`, `is_survey_target`, `survey_note`, `region`.
- **Регион у наблюдения:** в `surveys` своего региона нет — берётся из `divisions.region` подразделения; фолбэк для импортных строк — разбор `Регион:` из примечания.
- **Импорт опроса зарплат:** `src/services/surveyImport.js` + `adminController.importSurvey`. Нераспознанный ID_Бизнес → `unit = "Обзор рынка — не распределено"` (`src/data/surveyImportLegend.json`), для него создаётся строка в `divisions`.
- **CSV дашборда** формируется в браузере (`exportDashboardCSV`); перед скачиванием `POST /api/dashboard/export-log` → `audit_log`.
