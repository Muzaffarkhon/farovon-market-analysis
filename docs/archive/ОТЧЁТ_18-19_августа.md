## 3. Что изменено в коде

Файл `Code.gs`, ~6200 строк. Все правки проверены прогоном в браузере: файл парсится,
окна собираются, их скрипты синтаксически верны.

### 3.1. Перенос строк — починен

Окно «Перенести строки» строило оба списка из листа «Подразделения». Сироты
(`Департамент развития (общий)`, `Финансовый департамент (общий)`) из этого листа
уже удалены, поэтому в списке «Откуда» их не было — выбрать было нечего.

Теперь функция отдельно собирает сирот и кладёт их в начало списка «Откуда»
отдельной группой с предупреждением. «Куда» — только действующие подразделения.

### 3.2. Назначение ответственных — новое окно

Пункт меню **«Назначить ответственных…»**.

Таблица подразделений, в третьей колонке поле с выпадающим списком всех 125 человек
из справочника; можно печатать фамилию — список фильтруется.

- Жёлтым — 20 подразделений без ответственного, всегда сверху.
- Серым — где один человек тянет 3 и больше подразделений.
- Пустое поле = не трогать. Выбрано — поле зеленеет, внизу счётчик.
- Галочка «только требующие внимания» снимается для показа всех 121.

При сохранении фамилия пишется и в «Подразделения», и в строки «Конкурентов» этого
подразделения. Учётки и статусы пересчитываются, новый ответственный сразу получает доступ.

### 3.3. Загрузчик оргструктуры — новое окно

Подменю **«Оргструктура → Загрузить новую оргструктуру…»**.

Порядок работы:

1. Открыть пункт. Если листа «Новая структура» нет — окно предложит создать.
2. Вставить на лист CSV: первая колонка — название с тире в начале
   (одно тире = уровень 1, два = уровень 2), вторая — руководитель, третья — HR BP.
3. Открыть пункт снова — окно покажет, **что произойдёт, до внесения изменений**:
   сколько станет всего, сколько добавится, переименуется, уйдёт в архив, и списком —
   какое название на какое меняется.
4. Нажать «Загрузить структуру».

Что соблюдается:

- **Переименование не рвёт связи.** `Отдел логистики продаж Худжанд` и
  `0207 Отдел логистики продаж Худжанд` опознаются как одно подразделение: ID остаётся,
  новое имя расходится по листам «Конкуренты», «Участники опроса», «Справочник должностей»,
  «Статус заполнения», «Обзор рынка», «Нужны руководители» и по справочнику.
  Работает и для номерных префиксов, и для подчёркиваний у заводов ЖБИ/РБУ.
- **Назначенные ответственные сохраняются.**
- **Подразделения без руководителя встают первыми строками** под шапкой.
- Формулы не перезаписываются, ID не переприсваиваются.

### 4.8. Бот

В журнале 19.08 00:14: `телеграм · ошибка опроса · Адрес недоступен: https://api.telegram.org/bot…`
Запрос к Telegram не прошёл вообще.

Замедление не в размере таблицы: бот при ответе читает только лист «Пароли (выдать)»,
124 строки, это доли секунды. Дело в лимитах Apps Script: таймер опроса срабатывает
раз в минуту, чаще Google не разрешает; суточная квота выполнения на `@gmail.com` —
90 минут, и опрос вместе с окнами быстрого ответа её постепенно выбирает. Когда квота
кончается, триггеры до конца суток не запускаются.

**Решение: вебхук через внешний релей** (Cloudflare Worker). Ответ мгновенный всегда,
квота почти не тратится. Напрямую вебхук на `/exec` не работает — Google отвечает
редиректом 302, а Telegram редиректы не следует.

- Колонки ID неприкосновенны: `V` в «Конкурентах», `A` в «Обзоре рынка».
- `SpreadsheetApp.flush()` перед чтением того, что только что записали, если в цепочке формулы.
- После любой правки кода — новое развёртывание, иначе `/exec` отдаёт старый код.
- Меню перестраивается только при открытии таблицы — после вставки кода `F5`.
