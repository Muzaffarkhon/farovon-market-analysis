## 1. Что сделано этой серией

### 1.1. Довели до конца незавершённую работу в новом клиенте (`web/`)

С прошлой сессии в рабочей копии копилось много несохранённых правок нового клиента — довели, проверили (тесты, типы, сборка) и закоммитили одним коммитом (`95b51c0`), затем смёржили `redesign/react` в `main` и запушили:

- Единый диалог подтверждения (`Confirm`) вместо `window.confirm` — с «опасным» вариантом для необратимых действий.
- Сортировка кликом по заголовку таблиц (`SortTh` + `useSort`) — подключена в пользователях, периодах, сотрудниках, бенчмаркинге.
- Модальный вариант диалогового окна (`Sheet variant="modal"`) — для форм, которые нужно читать, а не пролистывать.
- Анкета грейдирования — варианты ответа под перемешиваемыми буквами вместо баллов (защита от подглядывания и от «я поставил третий вариант» до итога комиссии).
- **Окно «разбивка по комиссии»** (`CommitteeBreakdownSheet`) — было создано в прошлой сессии, но нигде не подключалось (падала сборка: `declared but never read`). Довели: подключили к `GradingScreen`, открывается по клику на статус должности у тех, кто управляет грейдированием.
- На сервере: эндпоинты `restore-evaluation` и `committee-breakdown`, таблица `grading_reset_backup` (откат последнего сброса оценки).

### 1.2. Перенесли из старого клиента в новый: рассылка через Telegram

Раздел «Администрирование → Рассылка» (`web/src/features/admin/broadcast/`):

- История рассылок с раскрытием — кто получил, кто нет.
- Бэкенд не трогали — эндпоинты `/admin/broadcasts*` уже существовали.

### 1.3. Перенесли из старого клиента в новый: журнал изменений

## 2. Полный аудит: что ещё не перенесено из старого клиента в новый

Сверили все серверные `/api/*` маршруты с тем, что реально вызывается из `web/`. Список подтверждён построчно (не по памяти).

**Существенное:**
1. **Онбординг нового пользователя** — подтверждение ФИО, выбор своих подразделений, отметка «прошёл онбординг» при первом входе (`/auth/change-name`, `/auth/set-units`, `/auth/onboarded`). В новом клиенте экрана нет вообще.
2. **Живое обновление данных** — старый клиент периодически опрашивает `/live-signature` и сам обновляет экран при изменениях. Новый клиент грузит данные один раз при открытии.
3. **Привязка/отвязка Telegram из профиля** (`/telegram/link`, `/telegram/unlink`, `/telegram/bot-info`) — отсутствует в новом клиенте.

**Административное:**
4. **Конструктор ролей** (`/admin/roles`, `/admin/roles/:key/rename`, `/admin/roles/:key/delete`) — в новом клиенте можно только редактировать права существующих ролей, создать/переименовать/удалить роль нельзя.
5. **Справочники (компании/должности)** — инструмент объединения дублей и переименования записей в общих справочниках (`/admin/dictionary/:kind*`). Не путать со штатным расписанием из 1С — то уже перенесено (`StaffScreen`).
6. **Обслуживание и статус данных** (`/admin/maintenance`, `/admin/data-status`, `/admin/import-survey`) — служебные кнопки «запустить обслуживание», «статус загруженных данных», массовый CSV-импорт анкеты через админку.
7. **Бейдж непрочитанных** в админском инбоксе поддержки (`/admin/support/unread-count`) — сам инбокс работает, просто нет счётчика-уведомления рядом с пунктом меню.
8. **Смежные группы подразделений** (`/admin/divisions/adjacent-group*`) — объединение похожих подразделений (разные площадки одной сети) в одну карточку сравнения зарплат. Отображается в оргструктуре как карточка «Смежная · N площ.», задаётся полем `group_key` у подразделения. Ни отображения, ни редактирования в новом клиенте нет.

**Второстепенное:**
9. **Выгрузка в CSV** — у старого дашборда была кнопка экспорта сырых данных (`/dashboard/export-csv`, `/benchmarks/export`). Выгрузка реестра (`/registry/export`) уже перенесена, эти — нет.
10. **Персональные веса по должности** в бенчмаркинге (`/benchmarks/position-weights`) — сейчас можно менять веса источников целиком, override по одной конкретной должности нельзя.

**Полностью перенесено и работает:** анкета сбора данных, реестр, дашборды (кроме CSV-экспорта), координация, грейдинг с комиссией, риски, бенчмаркинг (кроме двух пунктов выше), поддержка (кроме бейджа), оргструктура (кроме смежных групп), рассылка, журнал изменений.
