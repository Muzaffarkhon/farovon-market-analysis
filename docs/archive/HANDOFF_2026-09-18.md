## 2. Что сделано этой серией

### 2.1. Блокировка Turso по квоте чтений
Аккаунт Turso (`muzaffarkhon`) исчерпал бесплатный лимит чтения строк (620+ млн строк прочитано за период) — весь аккаунт временно заблокирован (не только эта база). Причина — частый polling с фронтенда (см. §2.2 фикс). Пользователь оплатил платный план Turso — блокировка снята, данные не пострадали.

### 2.2. Снижение частоты опроса сервера (`7463054`, PR #84)
Чтобы не упираться в лимит повторно — увеличены интервалы polling на клиенте:
- `client/liveRefresh.js`: основной опрос дашборда/админки 20с → 45с, страховочная перерисовка 90с → 180с.
- `client/app.js`: опрос чата поддержки (админ и сотрудник, `startSupPoll`/`startMySupPoll`) 8с → 20с.

Логика перерисовки не менялась, только интервалы — на функциональность не влияет, только на задержку обновления.

### 2.3. Переезд проекта на новый аккаунт Vercel
Прежний Vercel-проект уткнулся в **два независимых лимита** бесплатного (Hobby) плана одновременно:
- Functions Storage 46 ГБ вместо 10 ГБ (накопление файлов функций от прошлых деплоев).
- Deployment Blocked с текста «commit author did not have contributing access... Hobby Plan does not support collaboration for private repositories» — коммиты мержились через GitHub API от имени, которое Vercel не считал участником проекта (см. §5, грабли).

Решение — пересоздать проект на новом аккаунте Vercel, подключить тот же GitHub-репозиторий. Сделано:
- Собраны переменные окружения: `TURSO_DATABASE_URL`/`TURSO_AUTH_TOKEN` — взяты заново из app.turso.tech (Connect), т.к. в старом проекте были сохранены типом **Secret** и невосстановимы через UI Vercel. `JWT_SECRET`, `TELEGRAM_WEBHOOK_SECRET` — сгенерированы заново (следствие: все пользователи разлогинены, ожидаемо). `TELEGRAM_BOT_TOKEN` — тот же, из @BotFather. `WEBAPP_URL` — новый адрес нового проекта. `PORT`/`NODE_ENV` — без изменений.
- **Грабля с генерацией секрета**: первая попытка `TELEGRAM_WEBHOOK_SECRET` через `[Convert]::ToBase64String(...)` дала символы `+`/`/`/`=`, Telegram отверг («secret token contains illegal characters» — разрешены только `A-Za-z0-9_-`). Пересгенерировано через `-join ((48..57)+(65..90)+(97..122) | Get-Random -Count 40 | % {[char]$_})`.
- Деплой на новом проекте прошёл успешно, вход подтверждён, вебхук Telegram переустановлен командой `setWebhook` с новым `url`/`secret_token` — ответ `{"ok":true,"result":true}`.

## 5. Грабли этой сессии (важно для будущих правок)

1. **Vercel Secret-переменные невосстановимы** — если переменная окружения сохранена с типом «Secret», её значение нельзя посмотреть в UI Vercel никогда, только пересоздать/взять из первоисточника (Turso, BotFather и т.п.). При заведении новых секретов на будущее стоит иметь в виду, что тип «Secret» — билет в один конец.
2. **Telegram secret_token: строгий набор символов** — только `A-Z a-z 0-9 _ -`, 1–256 символов. Base64-строки (со знаками `+/=`) не проходят валидацию Telegram API `setWebhook`.
3. **Vercel Hobby-план блокирует деплой при «чужом» авторе коммита** в приватном репозитории («Hobby Plan does not support collaboration for private repositories») — если коммиты мержатся через GitHub API/бота не от аккаунта-владельца Vercel-проекта, финальный деплой в прод может зависнуть в статусе Blocked, даже если Preview-деплой той же ветки собрался успешно. Стоит проверять статус прод-деплоя после каждого мержа, а не только Preview.
4. **Functions Storage на Vercel растёт от каждого прошлого деплоя**, не только от последнего — при частых деплоях бесплатный лимит (10 ГБ) можно исчерпать даже на небольшом проекте; периодическая чистка старых деплоев (или Pro-план) снимает это.
5. **Сетевые ограничения агентского окружения** — при работе из Claude Code (веб-сессия) исходящий трафик на `*.vercel.app` заблокирован политикой прокси; проверить работоспособность живого сайта можно только через скриншоты/действия самого пользователя, не напрямую curl/WebFetch.
