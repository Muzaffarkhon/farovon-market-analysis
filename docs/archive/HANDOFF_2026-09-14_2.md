### 2.4. Персональные права — новая фича (основной объём сессии)
Запрос пользователя: *«чтобы выдать доступ одному руководителю, приходится включать право всей роли»*.

**Схема:** новая таблица `user_capabilities(user_login, capability, granted_by, granted_at)` — точечная надбавка поверх `role_capabilities`. `hasCapability()` в `src/middleware/auth.js` теперь смотрит в обе таблицы (`UNION`). Один эндпоинт `POST /api/admin/user-capabilities` (`setUserCapabilities`) — полная замена набора прав сотрудника за вызов, по образцу `saveRoleCapabilities`; отдельных `grant`/`revoke` ручек больше нет (были и убраны в процессе переделки UI).

**UI** (админка → «Роли и доступы»): переключатель **«По ролям / Персонально»** в шапке той же вкладки (не отдельный экран). Режим:
- Слева — список сотрудников с поиском (фильтр по ФИО/логину).
- Справа — чек-лист прав выбранного сотрудника, сгруппированный по разделам:
  - права, уже полученные **по роли**, показаны отмеченными и заблокированными (`disabled`, метка «по роли») — не редактируются здесь, только на вкладке «По ролям»;
  - остальное — обычные чекбоксы личных прав, можно по одному, по чекбоксу «весь блок» (индетерминейт при частичном выборе), или кнопкой «Убрать все личные»;
  - если у группы ВСЕ права уже покрыты ролью — чекбокс «весь блок» для неё не рисуется (нечего переключать).
- Правки копятся в памяти, уходят одним запросом по «Сохранить» в шапке (как у ролей) — не по одному тычку на каждый чекбокс.

**Общий компонент `niceSelect`** получил опцию `search:true` (строка поиска сверху панели, для списков >6 пунктов) — переиспользована также в панели выдачи доступа к архивным периодам.

### 2.5. Бесшовное автообновление (по итогам жалоб пользователя на «дёрганье»)
`client/liveRefresh.js` (поллинг `/api/live-signature` раз в 20с + страховка 90с) раньше **безусловно** перерисовывал текущий раздел админки при любом срабатывании — это:
1. вырывало открытый выпадающий список из рук;
2. молча стирало несохранённые правки в матрице ролей/персональных прав;
3. на вкладке «Персонально» **сбрасывало режим обратно на «По ролям»** — объект состояния (`S.rc`) пересобирался с нуля при каждой перезагрузке и терял поле `mode` (это чисто клиентское поле, сервер о нём не знает);
4. во всех разделах админки (Оргструктура, Архив, Справочники, Блоки/Анкеты грейдирования, Журнал действий, Сервисные утилиты, Чат поддержки, Период сбора) показывало вспышку «Загрузка...» поверх уже отрисованных данных на каждый опрос.

Исправлено:
- `isUiBusy()` в `liveRefresh.js` теперь откладывает (не отменяет — ждёt 3с и проверяет снова) перерисовку, если: открыт `.nselect.open`, ИЛИ фокус в `input`/`textarea`/`select`/`contenteditable` где угодно в приложении, ИЛИ есть несохранённые правки (`rcIsDirty()`/`ucapIsDirty()` — новые глобальные хелперы в `app.js`, тот же diff, что использует кнопка «Сохранить»).
- `loadAdminRoles()` переносит `S.rc.mode` между перезагрузками вместо сброса.
- Во всех перечисленных разделах рендер-функции теперь показывают скелетон/спиннер **только на первый заход** — если данные уже есть в памяти (`S.adminDivs`, `S.adminArchive`, `S.dictItems`, `S.gbBlocks`, `S.gradingFactors`, `$('auditLogBox')` существует, `$('dataStatus')` существует, `S.supThreads`), повторный вызов просто освежает данные без разрушения разметки. Раздел «Период сбора» дополнительно кэширует последний ответ панели архивных доступов (`S.periodGrantsCache`) и показывает его сразу вместо «Загрузка…», пока летит свежий запрос.
- Проверено на каждом разделе через `javascript_exec`: наполнить `S.xxx` фейковыми данными, вставить маркер-контейнер (`#dictBox`/`#gbBox`/`#gfBox`/`#auditLogBox`/`#dataStatus`/`#supBox`), вызвать рендер-функцию напрямую, синхронно проверить, что маркер не стёрт скелетоном.

**Не доведено до идеала (сознательно, за пределами этой сессии):**
- Журнал действий (`renderAdminAudit`) — скелетон больше не мигает, но введённый поиск/фильтр/страница всё равно сбрасываются при фоновом обновлении (функция строит фильтры с нуля при каждом вызове, а не хранит их в `S`). Если это станет жалобой — нужно вынести `filterSearch/filterAct/pg` в `S.auditFilters`.
- Панель «Доступ к редактированию архива» (форма выдачи, два `niceSelect`) всё ещё коротко пустеет перед повторным заполнением — сам список грантов и список периодов уже кэшируются, а вот форма выдачи — нет. Малозаметно, но не идеально.

### 2.6. Донастройка чек-листа персональных прав (по свежим скриншотам пользователя)
`71d98ac` — два бага, оба видны только на реальных длинных русских подписях:
1. Прошлый фикс переполнения (раздел 2.4) закрыл только левый список сотрудников (`.r2-name`/`.r2-sub`) — сам чек-лист прав справа остался без `min-width:0`/`overflow-wrap` на тексте подписи (`.r2-cap span`, `.r2-group-t--check span`). Подписи вроде «Открытие/закрытие периода» (слеш без пробела — браузеру буквально некуда перенести строку без `overflow-wrap`) вылезали за рамку.
2. «Чекбоксы не в один ряд» — не связано с переносом текста: у заголовка блока (`.r2-group-t--check`) не было своего `padding`, а у обычного пункта (`.r2-cap`) был `padding: 7px 4px` — чекбоксы расходились по горизонтали ровно на эти 4px. Нашли не на глаз, а через `getBoundingClientRect().left` по всем чекбоксам сразу (см. грабли §5 ниже) — визуально 4px почти незаметны на скриншоте, а `.every(x => x === rects[0])` сразу показывает `false`.

## 3. Грабли этой сессии (важно для будущих правок)

1. **`[hidden]` атрибут проигрывает авторскому CSS-правилу с `display`.** Если у класса элемента в stylesheet явно задан `display: block/flex/...`, установка `el.hidden = true` НЕ скрывает элемент — правило `[hidden]{display:none}` живёт в таблице стилей браузера (user-agent origin) и в каскаде всегда проигрывает любому авторскому правилу той же специфичности или ниже, независимо от порядка. Ловили дважды: сначала в поиске `niceSelect` (`.nselect-opt{display:block}` — искали через `data-q`+`opt.hidden`, фильтр «работал» по данным, но визуально ничего не менялось), потом сознательно избежали той же ошибки в новом списке сотрудников персональных прав. **Правило на будущее:** если элемент, который нужно прятать/показывать через JS, имеет свой явный `display` в CSS — переключать через `el.style.display`, а не через `el.hidden`/`[hidden]`.
2. **CSS Grid тоже требует `min-width: 0` на детях**, как и flexbox (эту грабли уже ловили с flex в прошлых сессиях, теперь она же всплыла в `.roles2-list`/`.roles2-detail` — grid-колонки 260px/1fr). Без `min-width:0` grid-элемент не сжимается уже своего контента, и длинное ФИО/длинная подпись права раздувает колонку за пределы видимой рамки вместо переноса строки. **Важно:** `min-width:0` на колонке-контейнере НЕ распространяется вглубь сам по себе — каждый вложенный flex-ряд с текстом (`.r2-cap`, `.r2-group-t--check`) нуждается в своём `min-width:0`+`overflow-wrap:break-word` на элементе с текстом, иначе колонка сожмётся, а конкретная строка внутри всё равно вылезет. Ловили это дважды за сессию на одном и том же экране — сначала пофиксили колонку, пользователь прислал новый скриншот с тем же классом бага на соседнем блоке.
3. **Визуальные баги вида «не выровнено»/«не в ряд» — проверять `getBoundingClientRect()`, а не на глаз по скриншоту.** 4px расхождения слева у чекбоксов (разный `padding` соседних CSS-классов) почти не видно на сжатом скриншоте, а `.every(x => x === rects[0])` по всем `input.getBoundingClientRect().left` находит их мгновенно и однозначно.
4. **Дев-сервер (`node --watch`) не всегда подхватывает правки в `src/routes/`/`src/controllers/`** на этой машине — после изменения роутов иногда нужен ручной `preview_stop`+`preview_start`, а не просто ждать автоперезапуска.
5. **Порт 3000 почти всегда занят** — `preview_start` с автовыбором порта сам находит свободный, не бороться за 3000 специально.
6. Как и раньше: тестовые проверки авторизованных экранов — только через прямые вызовы сервис-слоя в обход HTTP, или инъекцию `S.token`+фейкового состояния в уже загруженный клиентский JS через `javascript_exec`. Логиниться по-настоящему нельзя (жёсткая политика, не «спросить лишний раз»).

## 4. Как продолжить в новом чате

```bash
cd farovon-market-analysis
git pull origin main       # 71d98ac или новее
```

Локальный запуск — через `preview_start` (не `npm start` руками, порт почти всегда занят). Миграции идемпотентны, гоняются при каждом старте сервера — таблица `user_capabilities` создастся сама.
