## 3. Как это устроено — коротко

- **Один Telegram-чат = один тред** (`support_threads.telegram_chat_id UNIQUE`), переоткрывается при новом сообщении, не плодится заново.
- **Кто это** определяется динамически JOIN'ом по `telegram_chat_id` на `users` (не отдельным полем на треде) — если сейчас этому chat_id соответствует активный сотрудник (через `/start`, привязку по номеру или ручную «Привязать к сотруднику»), тред и список показывают его ФИО вместо «Гость #N».
- **Уведомление C&B** (`notifySupportTeam`, всем admin/cb с привязанным Telegram) шлётся только в момент, когда тред создаётся или переоткрывается из `closed` — не на каждое сообщение. Логика открытия унифицирована в `openSupportThreadForGuest()` (используется и инлайн-кнопкой, и текстовой).
- **Быстрые фразы** — одна таблица `support_quick_replies` на два `audience`: `admin` (вставляются в поле ответа C&B, редактируются в открытом треде) и `guest` (клавиатура гостю в боте, редактируются на общем экране списка тредов). Один и тот же клиентский компонент `renderQuickReplyManager()` рисует обе панели.
- **Автообновление** (`supPollTick`, 8 сек) — тянет либо список тредов, либо открытый тред (смотря что открыто), плюс счётчик непрочитанного; сам останавливается, когда уходишь из раздела «Чат поддержки» (проверка `S.appView`/`S.adminTab` на каждом тике, а не явная отписка на всех путях выхода).
- **Капабилити:** весь раздел за `support:manage` (по умолчанию у `cb`, `admin` всегда).

## 4. Грабли, найденные в этой сессии (держать в голове на будущее)

1. **CSS-специфичность в рельсе:** `.rail-item span { flex:1; min-width:0 }` — общее правило для подписи пункта — перебивает точечные стили любого `<span>` внутри пункта рельсы (включая бейджи-счётчики). Нужен более специфичный селектор (`.rail-item .nav-badge-count`), а не просто добавить класс.
2. **Базовый `button{}`** в `style.css` навязывает `min-height: var(--tap)` (~44px под палец) и `padding: 0 14px` ВСЕМ кнопкам. Для компактных иконок-кнопок это надо явно сбрасывать (`min-height: auto; padding: 0`) — иначе элемент внутри может визуально схлопнуться (высота считается от `min-height`, а не от заданной `height`).
3. **Текст произвольной длины** (шаблоны фраз, вводимые пользователем) — переносить по словам (`white-space: normal; word-break: break-word`), а не `nowrap + ellipsis`: если ряд не помещается по ширине, `flex-wrap` не спасает нерастяжимый текст, весь ряд вылезает за экран.
4. **Service Worker кэширует старый CSS/JS** локально при разработке — после правок стилей иногда нужно `unregister()` SW + `caches.delete()` в консоли браузера (или Ctrl+Shift+R), иначе видишь старую версию, хотя файл на диске уже другой. В проде решается само — `scripts/bumpVersion.js` меняет `CACHE_NAME` при каждом коммите.
5. **Тестирование через веб-хук `/api/telegram/webhook`** требует `TELEGRAM_WEBHOOK_SECRET` в `.env` — если его нет, любой прямой POST вернёт 401. Рабочий способ проверять логику бота без реального Telegram: временно добавить `exports.__testProcessUpdate = processTelegramUpdate;` в `telegramController.js`, подменить `telegramService.sendTelegramMessage`/`answerCallbackQuery` перед `require`, вызвать напрямую, убрать временный экспорт и тестовые строки из БД после.

## 6. Как продолжить в новом чате

```bash
cd farovon-market-analysis
git pull origin main       # 543644b или новее
```
Дать этот файл новому чату как контекст. Локальный запуск — `npm start` (порт из `.env`/`PORT`, часто занят другим проектом на 3000 — задать `$env:PORT="3001"` в PowerShell). Миграции (`src/db/migrate.js`) идемпотентны, гоняются при каждом старте сервера.
