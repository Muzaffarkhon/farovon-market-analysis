## 📌 1. Назначение и бизнес-контекст системы

Система **«Обзор рынка»** (ранее разрабатывавшаяся под рабочим названием *«Анализ рынка»*) предназначена для комплексного мониторинга, сбора, нормализации и аналитической обработки данных о заработных платах, структуре компенсационных пакетов (Net/Gross, фикс, бонусы, KPI), льготах (ДМС, питание, связь, ГСМ) и условиях труда компаний-конкурентов по всем направлениям бизнеса ГК «Фаровон».

### Ключевые задачи системы:
1. **Охват всей структуры холдинга**: ведение справочников по **326 подразделениям**, сгруппированным по функциональным направлениям и смежным производственным площадкам.
2. **Делегирование и каскадирование**: возможность для руководителей департаментов/дирекций (`dir_head`) назначать ответственных сотрудников (`user`) на конкретные подразделения без передачи избыточных прав администрирования.
3. **Двухшаговый сбор рыночных данных**:
   - *Шаг 1 (Участники рынка)*: выбор и валидация компаний-конкурентов по сегменту и региону с отметкой актуальности (актуально / не актуально / в стоп-листе).
   - *Шаг 2 (Данные по рынку)*: заполнение зарплатных вилок (`Min`, `Median`, `Max`), налогового режима, периодичности бонусов и набора льгот по штатным должностям подразделения.
4. **Смежные производственные площадки**: оптимизация ввода для однотипных подразделений (например, службы охраны «Анхор», «ТМК», «Фаровон», «Навобод») за счёт объединения перечня должностей и подсказок компаний в 1 клик без смешивания фактических окладов.
5. **C&B Аналитика и бенчмаркинг**: расчёт рыночных перцентилей (P25, P50/Медиана, P75), построение Box-Plot диаграмм, анализ размаха рыночных вилок (%), оценка воронки охвата и выгрузка сводных отчётов в Excel/CSV.
6. **Омниканальность**: одновременная бесшовная работа через десктопный/мобильный веб-браузер и внутри **Telegram Mini App** с привязкой аккаунтов по номеру телефона и командами Telegram-бота.

## 🕰️ 2. Хронология эволюции проекта (18.08.2026 — 25.08.2026)

### Этап 1. Аудит и отказ от Google Apps Script (18–19 августа 2026 г.)
* **Исходное состояние**: Система функционировала на базе Google Таблиц (19 листов) и скриптов Google Apps Script (`Code.gs`, ~8 000 строк).
* **Проблемы**: Лимиты Google по времени выполнения скриптов (6 мин), периодические 302-редиректы, задержки UI при открытии (до 10–15 сек), риск случайного повреждения структуры ячеек и формул пользователями, отсутствие надёжного разграничения прав.
* **Результат этапа**: Полная выгрузка и дедупликация сырых данных (326 подразделений, 111+ пользователей, 3 600+ записей конкурентов, штатные расписания), проектирование автономной реляционной архитектуры.

### Этап 2. Создание Node.js SPA & Cloudflare Worker (20–21 августа 2026 г.)
* Разработка автономного бэкенда на Node.js / Express 4.x и базы SQLite.
* Попытка запуска гибридного решения на Cloudflare Workers.
* Создание аналитического дашборда C&B, модуля авторизации с JWT и базовой панели администратора.

### Этап 3. Аудит продакшена и переход на Turso LibSQL (22–23 августа 2026 г.)
* **Проблема бесплатного хостинга**: При использовании локального SQLite-файла внутри контейнера Render.com данные сбрасывались при каждом перезапуске (эфемерая файловая система).
* **Архитектурное решение**: Перенос базы данных на облачный распределённый кластер **Turso LibSQL** (AWS EU-West / Frankfurt).
* Отключение Cloudflare Worker и стандартизация единого продакшн-сервера на Render.com (`https://farovon-market-analysis.onrender.com`).
* Подключение UptimeRobot для предотвращения засыпания инстанса.

* **Runtime**: Node.js v20+ (LTS).
* **Веб-фреймворк**: Express 4.21.2.

* **CI/CD и хостинг**: GitHub + Render.com Web Service (Auto Deploy on push to `main`).

## 👥 4. Ролевая модель и матрица возможностей (RBAC)

Права доступа в системе разделены на системные роли и детальную матрицу возможностей (`capabilities`):

```javascript
// src/config/capabilities.js
const CAPABILITIES = {
  admin: [
    'dashboard.view', 'dashboard.export',
    'survey.view_all', 'survey.edit_all',
    'org.view_all', 'org.manage_all',
    'users.view_all', 'users.manage_all',
    'dictionaries.manage', 'service.tools'
  ],
  cb: [
    'dashboard.view', 'dashboard.export',
    'survey.view_all', 'org.view_all'
  ],
  dir_head: [
    'dashboard.view_own_dir',
    'survey.view_own_dir', 'survey.edit_own_dir',
    'org.view_own_dir', 'org.assign_responsibles' // Назначение ответственных внутри направления
  ],
  hrbp: [
    'dashboard.view_own_units',
    'survey.view_own_units',
    'org.view_own_units',
    'telegram.send_reminders' // Рассылка напоминаний должникам
  ],
  user: [
    'survey.view_assigned_units',
    'survey.edit_assigned_units'
  ]
};
```

### Подробное описание сценариев по ролям:

1. **Главный администратор (`admin`)**:
   - Полное управление пользователями: создание, редактирование, сброс паролей, мягкое удаление в архив, восстановление.
   - Оргструктура: назначение руководителей, ответственных, HR BP и смежных групп (`group_key`) по всем 326 подразделениям.
   - Сервисные инструменты: нормализация названий компаний, загрузка штатного расписания, раздача базового пула компаний по направлениям с безопасным откатом, просмотр журнала аудита.
   - Защита: учётную запись `admin` программно запрещено деактивировать, архивировать или понижать в роли.

2. **C&B Аналитик (`cb`)**:
   - Полный доступ к аналитическому дашборду по всей компании в реальном времени.
   - Перцентильные шкалы (Min, P25, Медиана, P75, Max, размах вилки в %), сравнение структуры льгот и бонусов.
   - Выгрузка сводных отчётов в Excel / CSV (с поддержкой UTF-8 BOM для корректного открытия в Excel).

3. **Руководитель направления / дивизиона (`dir_head`)**:
   - Доступ к отдельному пункту меню **«Назначить ответственных»**.
   - Возможность закрепить ответственного сотрудника за любым подразделением своего направления.
   - В пикере сотрудников отображаются **только сотрудники его направления** (исключена путаница с сотрудниками других дирекций).

4. **HR Business Partner (`hrbp`)**:
   - Мониторинг прогресса заполнения рыночных данных по закреплённым подразделениям.
   - Контроль наличия назначенных ответственных.
   - Отправка персональных и массовых напоминаний в Telegram в один клик.

5. **Ответственный за подразделение (`user`)**:
   - Работа со своими подразделениями через двухшаговый мастер:
     - *Шаг 1*: Отбор конкурентов (с подсказками компаний из смежных площадок).
     - *Шаг 2*: Ввод зарплат и условий по штатным должностям (с объединённым справочником смежной группы).

## 🗄️ 5. Схема базы данных (Turso LibSQL)

```sql
-- 1. Пользователи системы
CREATE TABLE IF NOT EXISTS users (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  login TEXT UNIQUE NOT NULL,
  password_hash TEXT NOT NULL,
  fio TEXT NOT NULL,
  role TEXT NOT NULL DEFAULT 'user',      -- admin | cb | dir_head | hrbp | user
  phone TEXT DEFAULT '',
  units TEXT DEFAULT '',                   -- Список закреплённых подразделений (через точку с запятой)
  active INTEGER NOT NULL DEFAULT 1,       -- 1 = активен, 0 = в архиве (soft delete)
  telegram_chat_id TEXT DEFAULT '',
  telegram_username TEXT DEFAULT '',
  created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
  updated_at DATETIME DEFAULT CURRENT_TIMESTAMP
);

-- 2. Подразделения оргструктуры (326 подразделений)
CREATE TABLE IF NOT EXISTS divisions (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  num INTEGER,
  unit TEXT UNIQUE NOT NULL,               -- Полное название подразделения
  dir TEXT NOT NULL,                       -- Направление / Дирекция
  head TEXT DEFAULT '',                    -- Руководитель направления
  resp TEXT DEFAULT '',                    -- Ответственный за заполнение обзора
  hrbp TEXT DEFAULT '',                    -- Закреплённый HR BP
  note TEXT DEFAULT '',
  group_key TEXT DEFAULT '',               -- Ключ смежной группы (например: "Служба охраны")
  created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
  updated_at DATETIME DEFAULT CURRENT_TIMESTAMP
);

-- 3. Участники рынка / Конкуренты по подразделениям
CREATE TABLE IF NOT EXISTS competitors (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  unit TEXT NOT NULL,                      -- Привязка к подразделению
  company TEXT NOT NULL,                   -- Название компании-конкурента
  segment TEXT DEFAULT '',                 -- Сегмент рынка
  region TEXT DEFAULT '',                  -- Регион
  source_type TEXT DEFAULT '',             -- Источник данных
  actual TEXT DEFAULT 'не проверено',      -- актуально | не актуально | не проверено | стоп-лист
  comment TEXT DEFAULT '',
  created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
  updated_at DATETIME DEFAULT CURRENT_TIMESTAMP,
  UNIQUE(unit, company)
);

-- 4. Штатное расписание подразделений
CREATE TABLE IF NOT EXISTS unit_positions (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  unit TEXT NOT NULL,                      -- Подразделение
  position TEXT NOT NULL,                  -- Штатная должность
  code TEXT DEFAULT '',                    -- Уникальный код позиции
  created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
  UNIQUE(unit, position)
);

-- 5. Заполненные зарплатные анкеты по рынку
CREATE TABLE IF NOT EXISTS surveys (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  unit TEXT NOT NULL,
  company TEXT NOT NULL,
  position TEXT NOT NULL,
  salary_min REAL DEFAULT 0,
  salary_max REAL DEFAULT 0,
  salary_median REAL DEFAULT 0,
  tax_type TEXT DEFAULT 'Net',             -- Net (на руки) | Gross (до вычета)
  bonus_type TEXT DEFAULT 'отсутствует',   -- ежемесячный | квартальный | годовой | KPI
  bonus_amount REAL DEFAULT 0,
  benefits TEXT DEFAULT '[]',              -- JSON-массив льгот (ДМС, питание, связь, ГСМ)
  comment TEXT DEFAULT '',
  author_login TEXT NOT NULL,
  created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
  updated_at DATETIME DEFAULT CURRENT_TIMESTAMP,
  UNIQUE(unit, company, position)
);

-- 6. Справочники компаний, должностей, сегментов и регионов
CREATE TABLE IF NOT EXISTS dictionary_companies (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  name TEXT UNIQUE NOT NULL,
  segment TEXT DEFAULT '',
  region TEXT DEFAULT '',
  code TEXT DEFAULT ''
);

CREATE TABLE IF NOT EXISTS dictionary_positions (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  name TEXT UNIQUE NOT NULL,
  category TEXT DEFAULT '',
  code TEXT DEFAULT ''
);

-- 7. Периоды сбора данных
CREATE TABLE IF NOT EXISTS survey_periods (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  name TEXT NOT NULL,
  start_date DATE NOT NULL,
  end_date DATE NOT NULL,
  is_active INTEGER DEFAULT 1
);

-- 8. Журнал аудита действий (Audit Log)
CREATE TABLE IF NOT EXISTS audit_log (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  login TEXT NOT NULL,
  action TEXT NOT NULL,
  detail TEXT DEFAULT '',
  created_at DATETIME DEFAULT CURRENT_TIMESTAMP
```

## 🔌 6. Реестр REST API эндпоинтов (33 маршрута)

Все эндпоинты покрыты авторизацией Bearer JWT и автоматической проверкой ролей.

### 🔐 6.1. Аутентификация и сессии (`/api/auth`)
* `POST /api/auth/login` — вход по логину и паролю. Возвращает JWT токен и полный пользовательский payload.
* `GET /api/auth/resume` — восстановление сессии по активному токену (быстрый старт SPA).
* `POST /api/auth/change-password` — смена пароля текущего пользователя.
* `POST /api/auth/link-telegram` — генерация токена для привязки Telegram-аккаунта.
* `POST /api/auth/unlink-telegram` — отвязка аккаунта от Telegram.

### 📋 6.2. Опрос и заполнение данных (`/api/survey`)
* `GET /api/survey/units` — список доступных пользователю подразделений с прогрессом заполнения.
* `GET /api/survey/competitors` — список участников рынка по выбранному подразделению (с учётом подсказок смежной группы).
* `POST /api/survey/save-competitor` — сохранение/обновление карточки конкурента (актуальность, комментарий).
* `POST /api/survey/save-details` — сохранение зарплатной анкеты по должности (вилки, бонусы, льготы).
* `POST /api/survey/delete-details` — удаление введённой анкеты по должности.
* `GET /api/survey/positions` — перечень штатных должностей подразделения (и всей смежной группы).

### 📈 6.3. Аналитика и Дашборд (`/api/dashboard`)
* `GET /api/dashboard/overview` — общие метрики: % заполненности, количество участников, охват отделов.
* `GET /api/dashboard/distribution` — перцентильный анализ зарплат (Min, P25, Медиана, P75, Max) по должностям.
* `GET /api/dashboard/funnel` — воронка заполнения в разрезе HR BP и дирекций.
* `GET /api/dashboard/extended` — расширенная сводка для администратора и C&B аналитика.
* `GET /api/dashboard/export-csv` — потоковая выгрузка всех собранных данных в CSV (Excel UTF-8 BOM).

### ⚙️ 6.4. Панель управления Администратора (`/api/admin`)
* `GET /api/admin/users` — список всех пользователей с подразделениями и статусами.
* `POST /api/admin/save-user` — создание или обновление учётной записи пользователя.
* `POST /api/admin/archive-user` — перевод пользователя в архив (`soft delete`).
* `POST /api/admin/restore-user` — восстановление пользователя из архива.
* `POST /api/admin/reset-password` — мгновенный сброс пароля пользователя администратором.
* `GET /api/admin/divisions` — список всех 326 подразделений с ответственными лицами и группами.
* `POST /api/admin/save-division` — обновление ответственного, HR BP, руководителя и `group_key`.
* `GET /api/admin/periods` — управление кампаниями сбора данных.
* `POST /api/admin/save-period` — создание / переключение активного периода сбора.
* `GET /api/admin/audit-log` — получение журнала действий пользователей.
* `POST /api/admin/maintenance/clean-segments` — сервисная утилита нормализации справочника компаний.
* `POST /api/admin/maintenance/fix-links` — утилита синхронизации связей с оргструктурой.
* `POST /api/admin/maintenance/import-staffing` — загрузка штатного расписания.
* `POST /api/admin/maintenance/distribute-companies` — раздача базового пула компаний по направлениям.
* `POST /api/admin/maintenance/undo-distribute` — безопасный откат раздачи компаний.

### 📚 6.5. Справочники (`/api/dictionaries`)
* `GET /api/dictionaries/companies` — получение полного справочника компаний.
* `GET /api/dictionaries/positions` — получение справочника штатных должностей.
* `POST /api/dictionaries/manage` — добавление/редактирование элементов справочников.

### 🤖 6.6. Интеграция с Telegram (`/api/telegram`)
* `POST /api/telegram/webhook` — обработчик входящих сообщений и команд бота (`/status`, `/unlink`, `/help`, контакт).
* `POST /api/telegram/send-reminders` — запуск рассылки уведомлений должникам от имени HR BP.

### 💓 6.7. Системный мониторинг (`/health`)
* `GET /health` — проверка доступности сервера, связи с Turso LibSQL, версии (`2.2.0`) и времени последнего пинга от UptimeRobot.
