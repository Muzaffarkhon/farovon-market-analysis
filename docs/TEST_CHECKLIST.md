# Чек-лист тестирования системы «Обзор рынка вознаграждений»

Обновлено: 2026-09-13. Отмечать `[x]` по мере прохождения. Если что-то не работает — фиксировать шаги воспроизведения.

---

## 1. Вход и роли

- [ ] Вход под каждой ролью: `admin`, `cb`, `hrbp`, `dir_head`, обычный сотрудник — меню и разделы соответствуют правам роли
- [ ] Неверный логин/пароль — понятная ошибка
- [ ] Выход из системы — сессия действительно завершается
- [ ] Профиль пользователя открывается и данные корректны
- [ ] `/login` в Telegram-боте — привязка аккаунта работает, повторный `/login` не ломает существующую привязку

## 2. Анкеты подразделений (обычный сотрудник / HR BP)

- [ ] Список «Подразделения» открывается, отражает реальную оргструктуру
- [ ] Заполнение анкеты — сохранение черновика, потом дозаполнение
- [ ] Уход со страницы с несохранёнными изменениями — предупреждение не даёт потерять данные
- [ ] Отправка полностью заполненной анкеты — статус меняется на «отправлено»
- [ ] Попытка отправить анкету с пропущенными обязательными полями — блокируется с понятным сообщением
- [ ] «Сводка по HR BP» — правильно агрегирует прогресс по своим подразделениям
- [ ] Роль `dir_head` → «Назначить ответственных» — назначение сохраняется и виден результат у назначенного

## 3. Отчёт / прогресс (admin, cb)

- [ ] «Отчёт по подразделениям» показывает актуальный статус по всем подразделениям сразу
- [ ] Фильтры/поиск в отчёте работают

## 4. Дашборд

- [ ] Обзор — цифры совпадают с реальными данными (выборочная проверка 2-3 показателей вручную)
- [ ] Зарплатные вилки — отображаются корректно, без пустых/битых графиков
- [ ] По регионам — фильтрация по региону меняет данные
- [ ] Реестр данных — таблица открывается, экспорт (если есть) не падает
- [ ] Прогресс по HR BP — совпадает с данными из раздела 2/3
- [ ] Льготы и Бонусы — данные отображаются, не путаются между подразделениями

## 5. Бенчмаркинг

- [ ] Сравнение по должности — выбор должности подтягивает верные данные
- [ ] Сопоставление должностей — можно связать/переопределить сопоставление, сохраняется
- [ ] Источники и датасеты — список актуален, добавление/редактирование источника работает

## 6. Грейдинг

- [ ] «Оценка должностей» — доступна только с правом на грейдинг
- [ ] Открытие анкеты оценки для своего блока (комиссия) — доступно; для чужого блока — блокируется с понятным сообщением
- [ ] Для группы АУП теперь **4 фактора** (включая новый «Автономность принятия решений») — анкета показывает все 4, веса верные (0.35/0.30/0.15/0.20)
- [ ] Для производства — 4 фактора, вспомогательный/торговый — 3 фактора (не путаются местами)
- [ ] Расчёт взвешенного балла и уровня — сверить вручную хотя бы один пример на каждую группу
- [ ] Сохранение оценки должности — сохраняется, повторное открытие показывает те же ответы
- [ ] «Сводка по грейдам» — агрегаты совпадают с внесёнными оценками
- [ ] «Анкеты оценки» (подраздел «Грейдинг») — редактирование формулировок факторов/уровней сохраняется и сразу видно в анкете оценки
- [ ] «Блоки грейдирования» — создание/редактирование блока, привязка направлений к блоку
- [ ] Блок-специфичные переопределения формулировок (например, офисный блок) отображаются вместо общих — не потерялись после правок

## 7. Риски ключевого персонала

- [ ] «Ключевые сотрудники» — список, добавление/редактирование карточки риска
- [ ] Расчёт индекса риска (сумма 4 факторов 1–5) — сверить вручную один пример
- [ ] Статус (штатный / зона внимания / критический) — переключается на границах шкалы (8/13/20)
- [ ] «Тепловая карта рисков» — визуально соответствует данным списка

## 8. Администрирование — Пользователи

- [ ] Список всех пользователей — фильтры/поиск работают
- [ ] Создание нового пользователя — обязательные поля, дубликат логина отклоняется
- [ ] Редактирование пользователя (ФИО, роль, телефон, подразделение)
- [ ] Архивирование пользователя — уходит в «Архив», пропадает из основного списка, доступ у него блокируется
- [ ] Восстановление из архива — возвращается в работу корректно
- [ ] Роли и доступы (только admin) — изменение прав роли отражается в навигации у пользователей этой роли

## 9. Администрирование — Справочники

- [ ] Компании — CRUD
- [ ] Должности — CRUD, связь с анкетами/грейдингом не ломается после переименования
- [ ] Сегменты — CRUD
- [ ] Регионы — CRUD
- [ ] Удаление элемента справочника, который уже используется в данных — не ломает существующие записи (либо явно запрещено с понятным сообщением)

## 10. Администрирование — Период сбора, Оргструктура, Сервисные утилиты, Журнал действий

- [ ] Период сбора — открытие/закрытие периода, анкеты недоступны для редактирования вне периода (если так задумано)
- [ ] Оргструктура — дерево подразделений отображается верно, изменения сохраняются
- [ ] Сервисные утилиты — каждая утилита делает то, что заявлено, без падения сервера
- [ ] Журнал действий — фиксирует ключевые действия (создание/изменение/удаление), не пустой

## 11. Чат поддержки (админка)

- [ ] Список тредов открывается, автообновление работает без перезагрузки страницы (подождать 8+ сек, увидеть новое сообщение без ручного обновления)
- [ ] Открытие треда без ответа — счётчик непрочитанного сразу обнуляется (не только после ответа)
- [ ] Бейдж непрочитанных в рельсе/навигации — компактный кружок, не растянутая полоса, число не обрезается
- [ ] Ответ администратора уходит гостю в Telegram и виден в переписке сразу
- [ ] Привязка треда к сотруднику по ФИО — номер телефона сотрудника не затирается, если у треда его не было
- [ ] После привязки сотруднику приходит логин/пароль в том же формате, что и команда `/login`
- [ ] Тред показывает ФИО вместо «Гость #N», если чат сейчас привязан к активному сотруднику
- [ ] Быстрые ответы (админ) — вставляются в поле ответа, редактируются (добавление/удаление фразы), список сохраняется
- [ ] Быстрые вопросы гостю — редактируются на экране списка тредов, изменения сразу видны в Telegram-клавиатуре у нового гостя
- [ ] Текст в чипах быстрых ответов/вопросов не обрезается на длинных фразах (перенос по словам)
- [ ] Иконка карандаша/удаления в панели быстрых фраз видна и кликабельна (не схлопнута)
- [ ] Закрытие треда — статус меняется, при новом сообщении гостя тред переоткрывается (не плодит дубль)

## 12. Telegram-бот (сторона гостя/сотрудника)

- [ ] `/start` — новый пользователь видит клавиатуру «Отправить номер телефона» + «Написать администратору» сразу, без предварительной неудачной попытки
- [ ] Отправка контакта с номером, который совпадает с сотрудником — авто-логин/привязка проходит
- [ ] Отправка контакта с номером, который НЕ совпадает — понятное гостю сообщение (без упоминания админки/HR-панели), тред создаётся, админам приходит уведомление
- [ ] Кнопка «Написать администратору» (текстовая, на клавиатуре) — открывает/переоткрывает тред, показывает быстрые вопросы
- [ ] Инлайн-кнопка «Написать администратору» (если ещё есть отдельно) — тот же результат
- [ ] Повторные сообщения гостя в уже открытый тред — админам НЕ приходит повторное уведомление на каждое сообщение (только при открытии/переоткрытии)
- [ ] Тап по быстрому вопросу в Telegram — вопрос сразу отправляется как сообщение
- [ ] Долгая переписка (5+ сообщений туда-обратно) — ничего не путается местами, история цела

## 13. Кросс-функциональные / регрессионные проверки

- [ ] Мобильная версия (узкий экран) — нижняя полоса вкладок, кнопка «Ещё», кнопка «Админка» с выпадашкой работают
- [ ] Меню «⋮» на десктопе — показывает все доступные разделы согласно правам роли
- [ ] Хлебные крошки для «Анкеты оценки» / «Блоки грейдирования» показывают «Грейдинг → …», а не «Администрирование»
- [ ] После правок стилей/скриптов — проверить в обычном (не dev) режиме, что нет визуальных сюрпризов от старого кэша Service Worker
- [ ] Работа под слабым/нестабильным интернетом (мобильный трафик) — авто-обновление чата не заваливает сервер и не виснет UI
- [ ] Одновременная работа двух админов в одном треде поддержки — не теряются сообщения, не конфликтуют статусы прочитанности

## 14. Данные и целостность

- [ ] Экспорт данных (если есть в дашборде/реестре) открывается корректным файлом
- [ ] Удаление тестовых пользователей/записей после проверки — в БД не остаётся мусора с реальными боевыми данными (проект использует одну общую базу с продом)
- [ ] Права доступа (капабилити) — пользователь без нужного права не видит пункт меню И не может дёрнуть API напрямую (проверить хотя бы один эндпоинт вручную)
